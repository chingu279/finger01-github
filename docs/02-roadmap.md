# 02. 단계별 로드맵 — 14개를 한 번에 만들지 않는다

가장 흔한 실패는 14개를 한 달 안에 다 만들고, 데이터가 3일치뿐이라 아무것도 판단하지
못하는 상태로 방치하는 것이다. **데이터가 쌓이는 속도가 곧 만들 수 있는 속도다.**

각 단계는 **"다음 단계로 넘어가도 되는 조건"**을 가진다. 조건을 못 채우면 넘어가지 않는다.

---

## Phase 0 — 기반 (1주) · 에이전트 0개

에이전트를 하나도 만들지 않는다. 먼저 **측정 가능한 상태**를 만든다.

### 할 일
1. `python -m health init` → `data/profile.json` 을 직접 채운다.
   - 나이 · 성별 · 키 · **기저질환 · 복약 · 알레르기 · 금기 · 목표 · 비상연락처**
   - 이 값들이 모든 조언의 안전 경계다. 비워두면 시스템이 위험한 조언을 할 수 있다.
2. 무엇을 측정할지 정한다. **최대 5개.** 10개를 고르면 2주 안에 그만둔다.
   - 추천 시작 세트: 수면시간 · 안정시심박 · 활력(1~5) · 스트레스(1~5) · 자유메모
3. 어떻게 들어올지 정한다 (자동 > 수동).

### 완료 조건
- [ ] 프로필의 기저질환·복약·금기 칸이 채워져 있다
- [ ] 7일 연속 기록에 성공했다
- [ ] 하루 기록에 걸리는 시간이 **90초 이내**다

> **90초를 못 지키면 다음 단계로 가지 않는다.** 기록이 끊기면 이후 전부가 무의미하다.

---

## Phase 1 — MVP (2~3주) · 에이전트 4개

**목표: 매일 안전하게 답이 나온다.**

### 만드는 것
| 에이전트 | 이유 |
|---|---|
| `health-orchestrator` | 진입점 |
| `checkin-interviewer` | 기록이 계속되게 만든다 |
| `risk-triage` | **없으면 시스템을 켜면 안 된다** |
| `vitals-analyst` | 숫자를 말로 바꾼다 |

코어 코드(`triage.py`, `readiness.py`, `baseline.py`)는 이 단계에서 이미 다 있어야 한다.

### 이 단계의 함정
- 베이스라인 표본이 5일 미만이면 준비도가 `UNKNOWN` 으로 나온다. **정상이다.**
  이때 억지로 점수를 만들지 않는 것이 중요하다.
- 조언을 3개로 제한한다. 초반에 신나서 10개를 주면 2주 만에 앱이 소음이 된다.

### 완료 조건
- [ ] 21일 이상 데이터 (베이스라인이 의미를 갖는 최소치)
- [ ] `pytest tests -q` 전부 통과, 레드플래그 테스트 포함
- [ ] 준비도 밴드가 **체감과 어긋난 날이 주 2회 이하**
- [ ] 사용자가 "오늘의 3가지" 중 최소 1개를 실제로 실행

---

## Phase 2 — 개입 (4~6주) · 누적 8개

**목표: 상태를 읽는 데서 그치지 않고 바꾼다.**

### 추가하는 것
| 에이전트 | 우선순위 근거 |
|---|---|
| `wearable-ingest` | 수동 기록의 마찰을 없애야 6개월을 간다 |
| `sleep-coach` | **가장 먼저 손대야 할 도메인.** 수면이 HRV·기분·식욕·의지력을 전부 끌고 다닌다 |
| `exercise-coach` | 준비도 점수가 실제로 쓰이는 첫 지점 |
| `mind-coach` | 스트레스는 수면과 양방향으로 얽혀 있다 |

### 왜 수면부터인가
개입 하나가 다른 지표를 얼마나 끌고 오는지를 보면 수면이 압도적이다.
운동·식단을 먼저 손대면 수면 부족이 그 효과를 대부분 상쇄한다.

### 완료 조건
- [ ] 웨어러블 데이터가 자동으로 들어온다 (수동 입력 비중 < 30%)
- [ ] 개입 권고의 이행률이 **50% 이상**
- [ ] 최소 1개 지표에서 유의미한 변화 (예: 총 수면 +20분 이상, 4주 평균 기준)

---

## Phase 3 — 정밀화 (2~3개월) · 누적 11개

**목표: 일반론에서 나에게 맞는 조언으로.**

### 추가하는 것
| 에이전트 | 이유 |
|---|---|
| `nutrition-coach` | 데이터 마찰이 가장 큰 영역. 앞의 습관이 잡힌 뒤에 붙인다 |
| `clinical-record` | 검진 주기(연 1회)를 고려하면 지금쯤 첫 데이터가 들어온다 |
| `adherence-agent` | Phase 2에서 이행률이 정체되면 **바로 여기가 병목** |

### 이 단계에서 하는 일
- 준비도 `WEIGHTS` 를 개인화한다. 어떤 사람은 HRV가, 어떤 사람은 수면시간이 더 잘 맞는다.
- 트리아지 임계값을 조정한다. 오탐이 많으면 경보 피로로 전부 무시하게 된다.
- 프로필의 `sleep_need_min` 을 실측 기반으로 고친다 (기본 7.5시간은 추정치일 뿐이다).

### 완료 조건
- [ ] 90일 이상 데이터
- [ ] 지난 3개월 준비도-체감 일치율 80% 이상
- [ ] 트리아지 오탐(불필요한 경보)이 월 3회 이하

---

## Phase 4 — 자기개선 루프 (지속) · 누적 14개

**목표: 시스템이 스스로 나아진다.**

### 추가하는 것
| 에이전트 | 이유 |
|---|---|
| `insight-correlator` | 3개월 데이터가 있어야 상관이 의미를 갖는다 |
| `experiment-designer` | 가설을 증거로 바꾼다 |
| `reflection-agent` | **매주 시스템 자체를 고친다** |

### 주간 루프 (이때부터 이게 진짜 제품이다)
```
일요일  weekly-review
   ├─ 건강 결과 결산 (숫자)
   ├─ 개입 판정: 효과 있었다 / 없었다 / 판정 불가(이행 안 됨)
   ├─ 다음 주 실험 1개  → experiment-designer 등록
   ├─ 다음 주 집중 1개
   └─ 시스템 개선 1개  → 코드 수정 + 회귀 테스트 추가
```

### 완료 조건이 없다
Phase 4는 끝나지 않는다. 대신 **건강 지표**를 본다:
- 매주 시스템 개선 1건이 실제 커밋으로 남는가
- 실패로 판정된 실험이 전체의 30% 이상인가 (전부 성공이면 판정 기준이 물렁하다는 뜻)
- 3개월 전보다 조언이 구체적인가

---

## 요약표

| Phase | 기간 | 누적 에이전트 | 넘어가는 조건 |
|---|---|---|---|
| 0 기반 | 1주 | 0 | 7일 연속 기록, 하루 90초 이내 |
| 1 MVP | 2~3주 | 4 | 21일 데이터, 테스트 통과, 체감 일치 |
| 2 개입 | 4~6주 | 8 | 자동수집 70%, 이행률 50%, 지표 1개 개선 |
| 3 정밀화 | 2~3개월 | 11 | 90일 데이터, 일치율 80%, 오탐 월 3회 이하 |
| 4 자기개선 | 지속 | 14 | (끝나지 않음) 주 1회 시스템 개선 커밋 |

## 넘어가면 안 되는 신호

다음 중 하나라도 해당하면 **다음 Phase로 가지 말고 현재 Phase를 고친다.**
- 기록이 3일 이상 끊겼다 → 마찰이 너무 크다. 항목을 줄인다.
- 조언을 읽지 않고 넘긴다 → 조언이 현실에 안 맞는다. `adherence-agent` 로 원인을 찾는다.
- 알림을 무시하기 시작했다 → 경보 피로. 임계값을 올린다.
- "이거 맞나?" 하는 조언이 나왔다 → 안전 경계 점검. 프로필과 트리아지부터 본다.
