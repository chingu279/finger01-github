# 04. 안전과 개인정보

이 문서는 선택 사항이 아니다. **여기 적힌 경계를 지키지 못하면 시스템을 켜지 않는다.**

---

## 1. 이 시스템이 아닌 것

> 이 시스템은 **의료기기가 아니며 진단·치료를 제공하지 않는다.**
> 자기관리를 돕는 기록·분석 도구이며, 모든 의학적 판단은 의료 전문가와 함께 해야 한다.

- 진단명을 말하지 않는다. "~일 수 있으니 확인이 필요하다"까지가 한계다.
- 약물 용량을 조절하거나 처방약 중단을 권하지 않는다.
- "병원에 갈 필요 없다"는 판단을 내리지 않는다.
- 소비자 웨어러블 값은 의료기기 측정값이 아니다. 리포트에 항상 그렇게 표기한다.

### 특히 조심할 것 — 거짓 안심
이 시스템의 가장 위험한 실패는 잘못된 경보가 아니라 **"괜찮아 보인다"는 잘못된 안심**이다.
데이터가 부족할 때 시스템은 반드시 "판단 보류"라고 말해야 하고, 절대 "정상"이라고 하면 안 된다.
`readiness.compute()` 가 데이터 없이 `UNKNOWN` 을 반환하고, `triage` 가 "레드플래그 없음"이라고만
말하지 "괜찮습니다"라고 하지 않는 것이 이 원칙의 코드 구현이다.

---

## 2. 안전 아키텍처 — 왜 코드가 판정하는가

```
증상·수치 ──▶ triage.py (결정적 규칙)  ──▶ Severity  ──▶ 에이전트
                    │                                      │
                    │  ← 에이전트는 이 판정을            에이전트는
                    │     낮출 수 없다.                  상향만 가능
                    └─ 상향은 가능                          │
                                                            ▼
                                                    사용자에게 전달
```

LLM은 프롬프트·맥락·대화 길이에 따라 출력이 흔들린다. "흉통 + 식은땀"을 100번 중 1번
놓치는 것도 허용되지 않는다. 그래서 판정은 코드가, 전달은 에이전트가 한다.

`src/health/triage.py` 는 한 규칙이 예외로 죽어도 나머지 규칙이 계속 돌도록 감싸져 있고,
실패한 규칙 자체를 결과에 노출한다. **안전망이 조용히 사라지는 것이 최악이기 때문이다.**
(회귀 테스트: `tests/test_health.py::test_broken_rule_does_not_silence_other_rules`)

## 3. 심각도 단계

| 단계 | 의미 | 시스템 동작 |
|---|---|---|
| `EMERGENCY` | 즉시 응급 | 첫 문장이 행동 지시. 다른 모든 조언 차단 |
| `URGENT` | 24시간 내 | 운동 처방 전면 금지 (`blocks_exercise`) |
| `ROUTINE` | 수일 내 진료 권유 | 조언과 함께 전달 |
| `MONITOR` | 관찰 | 추세 기록 |

`python -m health triage` 는 심각도를 **종료 코드(0~3)**로 반환한다. 훅·스크립트에서 분기할 수 있다.

## 4. 현재 구현된 레드플래그

| 코드 | 트리거 | 단계 |
|---|---|---|
| `acs_suspect` | 흉통 + (방사통 \| 식은땀 \| 호흡곤란) | EMERGENCY |
| `stroke_fast` | 편측 마비 / 안면 처짐 / 언어장애 | EMERGENCY |
| `thunderclap_headache` | 갑작스러운 극심한 두통 | EMERGENCY |
| `anaphylaxis` | 기도 부종 / 전신 두드러기 | EMERGENCY |
| `seizure` | 경련·발작 | EMERGENCY |
| `suicidal_ideation` | 자살·자해 표현 | EMERGENCY |
| `hypoxia` | SpO2 < 90% | EMERGENCY |
| `severe_hypoglycemia` | 혈당 < 54 mg/dL | EMERGENCY |
| `syncope` / `bleeding` / `severe_abdominal_pain` / `dyspnea` | — | URGENT |
| `hypertensive_crisis` | ≥ 180/120 mmHg | URGENT |
| `high_fever` / `fever` (3일+) | ≥ 39.5℃ / ≥ 38℃ 지속 | URGENT |
| `rhr_elevated` | 안정시 심박 +15bpm 또는 +7bpm 3일 연속 | ROUTINE |
| `persistent_low_mood` | 2주간 기분 저하 60% 이상 | ROUTINE |
| `weight_loss` | 평소 대비 5% 감소 | ROUTINE |

**이 목록은 완전하지 않다.** 규칙 엔진은 안전 바닥이지 천장이 아니다.
`risk-triage` 에이전트가 규칙이 놓친 조합(증상 3개 이상 동시 발생, 급격한 악화,
취약 요인과의 결합, "평소와 완전히 다르다"는 직감)을 한 번 더 본다.

## 5. 정신건강

자살·자해 표현은 언제나 최고 우선순위다. 판단하거나 설득하지 않고 연결한다.

| 창구 | 번호 |
|---|---|
| 자살예방 상담전화 (24시간) | **109** |
| 정신건강 상담전화 | **1577-0199** |
| 응급의료 | **119** |

`mind-coach` 는 위기 상황을 직접 다루지 않고 `risk-triage` 로 즉시 넘긴다.

## 6. 도메인별 금지선

| 에이전트 | 절대 하지 않는 것 |
|---|---|
| `exercise-coach` | 통증을 참으라는 조언 · 주당 10% 초과 볼륨 증가 · 재활 필요 상태의 자가 처방 |
| `nutrition-coach` | 1,200kcal 미만 · 장기 단식 · 보충제 용량 처방 · 섭식장애 신호 시 계속 코칭 |
| `sleep-coach` | 수면제·멜라토닌 복용/용량 권유 |
| `adherence-agent` | 놓친 약을 어떻게 할지 지시 (이중 복용 위험) |
| `clinical-record` | "정상입니다" 단정 · 판독 불확실 항목의 추측 |
| 전체 | 진단명 확정 · 처방약 중단 권유 · "병원 갈 필요 없다" |

### 취약 집단
임신·수유·소아·고령·중증 만성질환(신장질환, 심부전, 조절되지 않는 당뇨)의 경우
운동·식이 처방을 하지 않고 **전문가로 안내한다.** 프로필의 `conditions` 가 이 판단의 근거다.
프로필이 비어 있으면 시스템은 이 판단을 할 수 없다 — 그래서 Phase 0에서 반드시 채운다.

## 7. 개인정보

건강 데이터는 한국 개인정보보호법상 **민감정보**다. 유출은 되돌릴 수 없다.

### 기본 원칙
1. **로컬 우선.** 기본 저장소는 로컬 파일이다. 클라우드는 명시적 선택 사항이다.
2. **커밋 금지.** `data/**` 는 `.gitignore` 로 전부 제외되어 있다. 이 줄을 지우지 않는다.
3. **최소 수집.** 어떤 결정을 바꾸지 않는 데이터는 수집하지 않는다.
4. **전송 금지.** 어떤 에이전트도 건강 데이터를 외부 서비스로 자동 전송하지 않는다.
   리포트는 파일로 만들고 **사용자가 직접** 전달한다.
5. **식별정보 마스킹.** 임상 문서의 주민등록번호·환자번호는 저장 전에 지운다.

### 커밋 전 확인
```bash
git status --short          # data/ 아래 파일이 보이면 안 된다
git diff --cached --stat
```
실수로 스테이징된 적이 있다면 `.gitignore` 만으로는 부족하다 — 이미 추적 중인 파일은
`git rm --cached` 로 빼야 한다.

### 백업
```bash
tar czf - data | age -p > health-backup-$(date +%F).tar.gz.age   # age 또는 gpg
```
평문 클라우드 동기화 폴더(구글 드라이브, 아이클라우드)에 `data/` 를 그대로 두지 않는다.

### 공유할 때
- 트레이너에게: 훈련부하·준비도만. 임상 정보 제외.
- 의사에게: 진료 전 요약 한 장 (`health-report` 스킬). 종이 또는 직접 전달.
- **가족·지인 공유 기능을 기본으로 만들지 않는다.** 필요하면 그때 명시적으로 만든다.

## 8. 안전 관련 코드를 고칠 때

`src/health/triage.py` 를 수정하는 것은 특별 취급한다.

1. 규칙을 **완화**할 때는 반드시 근거를 커밋 메시지에 남긴다.
2. 모든 변경에 **회귀 테스트를 함께 추가**한다. 테스트 없는 안전 규칙 변경은 머지하지 않는다.
3. 기존 레드플래그 테스트를 삭제하지 않는다. 조건을 바꿔야 한다면 새 테스트를 추가한다.
4. `reflection-agent` 가 오탐을 이유로 임계값 상향을 제안하더라도,
   **EMERGENCY 규칙은 오탐을 이유로 완화하지 않는다.** 경보 피로보다 미탐이 훨씬 비싸다.

```bash
python -m pytest tests -q     # 커밋 전 항상
```
