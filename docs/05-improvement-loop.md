# 05. 지속 개선 루프 — 시스템이 스스로 나아지게 만들기

대부분의 건강 앱은 **1주차 수준에서 영원히 멈춘다.** 데이터는 쌓이는데 조언은 첫날과 같다.
이 문서는 그걸 막는 장치다.

## 세 개의 루프

```
 ┌───────── 일간 (분 단위) ────────┐
 │ 기록 → 판정 → 조언 → 이행 기록  │      "오늘 뭘 할까"
 └────────────┬───────────────────┘
              │
 ┌────────────▼──── 주간 (주 1회) ──────────┐
 │ 회고 → 개입 판정 → 실험 등록 → 계획 수정  │  "무엇이 나에게 효과 있나"
 └────────────┬─────────────────────────────┘
              │
 ┌────────────▼──── 분기 (3개월) ───────────┐
 │ 목표 재설정 → 가중치 재보정 → 규칙 개정   │  "시스템 자체가 맞나"
 └──────────────────────────────────────────┘
```

세 루프의 주기가 다른 이유: **생체 신호는 하루 단위로 노이즈고, 주 단위로 신호이며,
분기 단위로 추세다.** 매일 가중치를 고치면 노이즈를 학습한다.

---

## 루프 1 — 일간

목적은 개선이 아니라 **연속성**이다. 하루하루의 목표는 "기록이 끊기지 않는 것" 하나다.

```bash
./health brief
```
팩트시트를 받고 → `checkin-interviewer` 가 질문 3개 → `orchestrator` 가
"오늘의 3가지" → 밤에 이행 여부 기록.

**조언은 3개를 넘기지 않는다.** 사람에게 5개를 주면 0개를 한다.
그리고 반드시 **이행 여부를 기록**한다. 이게 없으면 주간 루프가 아무것도 판정할 수 없다.

```bash
./health log --set 'adherence.plan_completed=취침 23시,아침 산책' \
                     --set 'adherence.plan_skipped=명상'
```

## 루프 2 — 주간 (핵심)

`reflection-agent` 가 3층으로 회고한다.

### 1층 · 건강 결과
숫자로만. "좋아진 것 같다"는 회고가 아니다.

### 2층 · 개입 효과 — 판정 3분류
| 판정 | 조건 | 다음 행동 |
|---|---|---|
| **효과 있었다** | 이행됨 + 지표 개선 | 유지·확대 |
| **효과 없었다** | 이행됨 + 지표 변화 없음 | 중단, 다른 것 시도 |
| **판정 불가** | 이행 안 됨 | `adherence-agent` 로. 효과 문제가 아니라 실행 문제 |

> **이행되지 않은 권고를 "효과 없음"으로 처리하는 것이 가장 흔한 분석 오류다.**
> "수면제한요법은 효과 없었다"가 아니라 "3일밖에 안 했다"가 사실이다.

### 3층 · 시스템 자체
여기가 이 시스템을 다른 앱과 구별짓는 층이다. 매주 이 다섯 가지를 묻는다.

| 질문 | 발견하면 고칠 곳 |
|---|---|
| 어떤 데이터가 계속 비어 있나 | 수집 경로 · 체크인 질문 축소 |
| 어떤 조언이 반복되는데 매번 무시되나 | 그 조언은 현실에 안 맞는다. 코치 프롬프트 수정 |
| 어떤 알림이 소용없었나 | 경보 피로. `triage.py` 임계값 상향 (단, EMERGENCY 제외) |
| 준비도가 체감과 어긋난 날은 | `readiness.WEIGHTS` / `BANDS` 재보정 |
| 트리아지가 놓치거나 과하게 잡은 것은 | `triage.py` 규칙 추가·수정 + **회귀 테스트** |

**개선 제안은 파일과 변경 내용으로 쓴다.** "더 개인화하면 좋겠다"는 제안이 아니다.
"`WEIGHTS['sleep.total_min']` 을 0.16 → 0.22로. 최근 8주간 수면시간 z가 체감 활력과
가장 잘 맞았기 때문" 이 제안이다.

### 매주 바꾸는 것은 최대 3개
매주 하나씩 나아지면 1년에 52번 나아진다. 10개를 바꾸면 무엇이 효과였는지 영원히 모른다.

## 루프 3 — 분기

- **목표 재설정.** 3개월 전 목표가 지금도 맞는가.
- **가중치 재보정.** 8~12주 데이터로 어떤 지표가 실제로 체감을 예측했는지 본다.
- **개인 상수 갱신.** `sleep_need_min`, `max_hr`, 카페인 커트오프 시각 — 전부 실측으로 교체한다.
- **에이전트 통폐합.** 3개월간 한 번도 안 쓴 에이전트는 지운다. 유지비가 든다.
- **검진 반영.** 연 1회 검진 결과를 `clinical-record` 로 넣고 프로필을 갱신한다.

## N-of-1 실험 — 추측을 증거로

이 시스템이 일반 건강 앱과 갈리는 지점이다. 인구집단 평균이 아니라 **나에게** 효과가 있는지를 본다.

### 규칙
1. **한 번에 하나의 변수만.**
2. **결과 지표를 미리 하나 정한다.** 실험 후에 좋아 보이는 지표를 고르는 건 자기기만이다.
3. **최소 기간**: 각 조건 7일 이상, 총 2~4주. 주중/주말 리듬을 덮으려면 최소 1주다.
4. **판정 기준을 사전에 쓴다.** 기준 없이 시작한 실험은 항상 "효과 있었다"로 끝난다.
5. **설계**: ABAB(되돌릴 수 있는 개입, 인과에 강함) > 교대 주 > AB(증거 약함, 그렇게 말한다)

### 좋은 첫 실험
카페인 커트오프 14시 · 취침 30분 앞당기기 · 아침 광노출 10분 · 저녁 산책 20분 ·
알코올 0주 · 취침 전 스크린 차단 · 아침 단백질 30g

전부 **되돌릴 수 있고, 측정 가능하고, 2주면 답이 나온다.**

### 실패를 실패라고 부르기
> **실패로 판정된 실험이 전체의 30% 미만이면 판정 기준이 물렁하다는 뜻이다.**

모든 실험이 성공하는 시스템은 아무것도 검증하지 못하는 시스템이다.
`experiment-designer` 의 가장 중요한 기능은 "효과 없음"을 그대로 보고하는 것이다.

## 시스템 건강 지표 (메타 지표)

건강 지표만 보면 안 된다. **시스템 자체의 건강**을 매달 본다.

| 지표 | 목표 | 나쁠 때의 의미 |
|---|---|---|
| 기록 연속성 | 주 5일 이상 | 마찰이 크다. 항목을 줄여라 |
| 하루 기록 시간 | 90초 이내 | 〃 |
| 권고 이행률 | 50% 이상 | 조언이 현실에 안 맞는다 |
| 준비도-체감 일치율 | 80% 이상 | 가중치 재보정 필요 |
| 트리아지 오탐 | 월 3회 이하 | 경보 피로 → 전부 무시하게 된다 |
| 트리아지 미탐 | **0** | 규칙 추가. 이건 타협 대상이 아니다 |
| 실험 실패율 | 30% 이상 | 낮으면 판정 기준이 물렁하다 |
| 주간 시스템 개선 커밋 | 주 1건 | 0이면 루프가 죽었다 |

## 흔한 실패 모드

| 증상 | 진짜 원인 | 처방 |
|---|---|---|
| 기록이 2주 만에 끊겼다 | 항목이 너무 많다 | 3개로 줄인다. 자동 수집으로 옮긴다 |
| 조언을 안 읽는다 | 매일 같은 말을 한다 | "어제와 달라진 것"만 말하게 바꾼다 |
| 알림을 무시한다 | 경보 피로 | 임계값 상향 (EMERGENCY 제외) |
| 데이터는 쌓이는데 변한 게 없다 | 주간 루프가 없다 | `weekly-review` 를 캘린더에 고정한다 |
| 조언이 늘 뻔하다 | 개인 데이터를 안 쓴다 | 조언에 z와 날짜를 인용하게 강제한다 |
| 실험이 전부 성공한다 | 기준을 사후에 정한다 | 등록 시점에 `success_criterion` 을 못 박는다 |
| 시스템을 못 믿겠다 | 데이터 없이 단정했다 | `confidence` 를 항상 노출한다 |

## 오늘 할 수 있는 일

이 루프를 시작하는 데 완성된 시스템이 필요하지 않다.

```bash
./health init -i
```
```bash
./health checkin
```

내일 또 한 줄. 7일 뒤 `./health score` 가 처음으로 의미를 갖는다.
21일 뒤 베이스라인이 신뢰할 만해진다. **그 전까지 필요한 건 코드가 아니라 연속성이다.**
